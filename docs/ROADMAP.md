# 신뢰 곡선 로드맵

다음 4단계는 **PROPOSAL**이다. M1 패키지 설치·자체 검사 성공이 단계 전체의 운영 통과를 의미하지 않는다. 단계 승격은 날짜·대상 revision·판정자·증거 경로가 있는 기록으로 남긴다. 앞 단계의 불변조건은 다음 단계에도 유지한다.

| 단계 | 진입 조건 | 수행 범위 | 종료 조건·판정 방법 |
|---|---|---|---|
| 1. 게이트 기계화 | 대상 프로젝트·마일스톤·변경 범위 확정, 실행 환경 확보 | typecheck/테스트/빌드/관련 E2E를 명시하고 CI 필수 체크에 연결. 사람이 PR 리뷰 | 정상 revision의 모든 필수 명령 exit 0. 타입 오류·테스트 실패·빌드 실패 fixture 각각 비영 종료 및 다음 단계 차단 증거. 사람의 PASS와 revision 일치 |
| 2. 리뷰 루프 자동화 | 1단계 통과 기록, worker/reviewer/코디네이터 역할과 보고 채널 확정 | read-only 리뷰→수정→재검증, 최대 3라운드, 단계 완료·하트비트 보고 | PASS 직행, REQUEST CHANGES 후 수정 PASS, 3라운드 미수렴 에스컬레이션 시나리오 모두 기대 전이. 지연 저장/중복 메시지/누락 worker_done fixture가 잘못된 완료를 만들지 않음. 실제 하네스 한 사이클 증거 |
| 3. PR 자동 병합 | 2단계 종료, 브랜치 보호·필수 CI·허용 변경 범위·롤백 계획과 사용자 병합 권한 확정 | 허용된 PR만 동일 head의 CI 성공+독립 PASS로 병합 | 격리 실험 PR에서 허용 변경만 병합. CI 실패·head 변경·충돌·금지 경로·승인 미보유 시 모두 차단. 병합 SHA와 롤백 훈련 결과 기록 |
| 4. 스킬 Eval | 단계별 실행 로그와 실패 분류·고정 fixture corpus·측정 예산 확보 | 실패 관찰→스킬/린트 개선→블라인드 실행→독립 judge | 고정 corpus의 필수 안전/상태 전이 위반 0. baseline 대비 성공률 비하락, 사전 합의 p95 시간·토큰 상한 준수. 모델·버전·seed·judge 근거·실패 사례 기록 |

## 단계별 제출 증거

1단계는 명령·cwd·환경 버전·종료 코드·실행 시간·로그 경로를 DoD 항목과 일대일 연결한다. “테스트가 있을 것”이나 빈 테스트 집합의 성공은 통과가 아니다. E2E가 필수인데 기기가 없으면 BLOCKED로 남기고 제외 승격은 범위 결정으로 기록한다.

2단계는 task ID, dispatch ID, round, reviewed revision, findings, 수정 커밋, 재검증 결과, 3자 디스크 확인을 묶는다. 실제 Slack 권한/채널이 설정된 경우 발송 영수증까지 확인한다. 미설정은 미발송 상태로 기록하고 live 보고 완료로 표현하지 않는다. 진행 상태만 전송하며 제한 원문은 싣지 않는다.

3단계는 CI가 성공한 head와 리뷰한 head와 병합할 head가 모두 같아야 한다. 새 커밋·base 변경·충돌 해소가 발생하면 기존 판정을 무효화하고 재검증·재리뷰한다. CONDITIONAL PASS, 누락된 필수 체크, 수동 우회로는 병합하지 않는다.

4단계의 블라인드 평가는 에이전트가 답을 외우지 못하도록 fixture와 정답을 분리한다. 최소 corpus는 정상 진행, 저장 지연, 이전 round 메시지 재도착, 필수 테스트 실패, 오래된 기억, scope 혼동, 3라운드 상한, Slack 중복 발송이다. 별도 judge를 사용하는 평가 운영은 이 단계 실행을 요청받았을 때 수행한다.

## 승격·강등 운영

각 단계의 결과는 `PASS | FAIL | BLOCKED`로 기록한다. 실패를 SKIP으로 바꿔 승격하지 않는다. 권한은 프로젝트·브랜치·작업 종류별로 정하며 다른 저장소에 전파하지 않는다. 운영에서 게이트 누락이나 잘못된 병합이 발견되면 자동화를 직전 검증 단계로 낮추고 회귀 fixture를 추가한다.

사전 합의된 시간·토큰 상한을 기록하지 않았다면 Eval 비교 판정은 BLOCKED다. 높은 PR 처리량은 품질의 대리 지표가 아니며, 실패 탐지율과 재현 가능한 결과를 우선한다. 반복 결함은 [운영 매뉴얼](workflow.md)에 따라 강한 검사로 승격한다.
